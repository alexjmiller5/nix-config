# Manual steps as a nix option, with generated MANUAL files

Design for replacing the two hand-written `MANUAL-<host>.md` files with a
declared `manual.steps` option, generated (still committed) manuals, and an
installed `manual-check` verifier.

## Problem

`MANUAL-macbook-air.md` and `MANUAL-mac-mini.md` mix four kinds of content
(bootstrap sequence, per-module human steps, "this list IS the declaration"
snapshots, architecture prose) in no fixed order. The nix module that needs a
step links to it only through ad hoc comments; shared steps are duplicated per
host and drift; nothing reports which steps a given machine still owes.

## Requirements (EARS)

1. The system shall let any nix-darwin or Home Manager module declare
   `manual.steps.<id>` with `title`, `owner`, `phase`, `body`, `verify`
   (optional), `redo` (optional) and `desktop` (bool).
2. The system shall render `MANUAL-<host>.md` from the evaluated host
   configuration, so a step appears on a host iff its declaring module is
   imported there.
3. The rendered file shall start with a generated-file callout linking the
   commit it was rendered from (`self.rev`, else `self.dirtyRev`).
4. The rendered file shall inline the hand-written
   `docs/manual/<host>-bootstrap.md` as the bootstrap phase.
5. The rendered file shall order steps by phase (`bootstrap`, `after-switch`,
   `snapshot`) then by `owner`, then by `id`.
6. When `just manual` runs, the system shall rewrite a `MANUAL-<host>.md` only
   if its body (everything below the header) changed.
7. When `switch-laptop` or `deploy` runs, the system shall regenerate the
   manuals first.
8. `nix flake check` shall fail when a committed manual body differs from a
   fresh render.
9. Each host shall install `manual-check`, which runs every step's `verify`
   and prints one line per step: `done`, `todo` or `manual` (no verify), with
   title and owner, exiting non-zero if any step is `todo`.
10. `manual-check` shall never perform a step, only verify it.
11. Architecture prose currently in the manuals shall move to `docs/` and be
    linked from the generated manual.

## Option schema

```nix
manual.steps.<id> = {
  title = "quota-axi Keychain grant";        # heading
  owner = "quota-axi";                       # module/package it belongs to
  phase = "after-switch";                    # bootstrap | after-switch | snapshot
  desktop = true;                            # needs logged-in desktop / Screen Sharing
  body = ''markdown...'';                    # the instructions
  verify = "quota-axi --provider claude | grep -qv keychain_access_required";  # optional
  redo = "after a fresh `/login` following `/logout`";                         # optional
};
```

The option module is written generically (`{ lib, config, ... }`) and
imported by both the darwin host modules and the Home Manager user module.
The renderer merges `config.manual.steps` (darwin) with
`config.home-manager.users.<user>.manual.steps` (HM). Duplicate ids across the
two trees are an evaluation error.

## Rendered layout

```
<!-- GENERATED by `just manual` from <sha-link>. Edit the declaring nix
     module or docs/manual/<host>-bootstrap.md, then rerun. -->
# MANUAL-<host>.md - steps nix cannot do

## Bootstrap            <- docs/manual/<host>-bootstrap.md verbatim
## After the first switch
### <title>  (owner · desktop|shell)
<body>
Verify: `cmd`           <- when set
Redo: <redo>            <- when set
## Snapshots (the list IS the declaration)
### ...
## Reference            <- fixed links into docs/
```

## Flake surface

- `packages.<system>.manual-<host>`: derivation producing `MANUAL-<host>.md`.
- `packages.<system>.manual-check-<host>` is not needed: `manual-check` is an
  HM-installed script whose step list is baked from the same evaluated config.
- `checks.<system>.manual-fresh`: compares committed bodies to fresh renders.
- justfile: `manual` recipe; `switch-laptop` and `deploy` call it first.

## Migration

Every existing step moves into its owner file with a `verify` where one is
checkable. Bootstrap sequences become `docs/manual/<host>-bootstrap.md`.
Reference prose becomes `docs/machine-vaults.md`, `docs/sip.md`,
`docs/tcc.md` (grant audit + purge), `docs/notifications.md`. Snapshot
sections move as `snapshot` steps unchanged; converting them to capture
scripts is a later, per-section follow-up.

## Testing

- `tests/manual-render.py`: renders a fixture with three steps across phases
  and owners and asserts header, ordering, verify/redo lines, and that a
  step absent from the fixture host does not render.
- `checks.manual-fresh` covers drift.
- E2E on both Macs: `manual-check` reports known-done steps as `done` and the
  quota-axi Keychain grant as `todo` until the human clicks Always Allow.
